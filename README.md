## Verification-first rule

Prometheus follows this progression:

```text
claim → observation → evidence → provenance → integrity → verified indicator → admissibility → value
```

No ecological claim, PRU maturity class, RAP inclusion, investor-facing interpretation, tokenized representation or capital-facing statement should bypass evidence, provenance, confidence scoring, admissibility and legal review.

## Pre-signing fields

Hash values, detached signatures, release timestamps and final manifest fields that depend on frozen files are treated as `PRE-SIGNING FIELD` values until the final freeze command is executed. This prevents the self-hash trap.

## Runtime boundary

The White Paper defines meaning. Holochain hApp, bridge, console, evaluation stack and pilot handoff repositories implement bounded runtime behavior. Runtime artifacts must not redefine Prometheus ontology.
